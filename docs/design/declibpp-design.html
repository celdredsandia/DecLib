DecLib++ class and interface design

Prepared for Chris23 October 2026Status: decided 23 October; phase 1 implemented 24 October
About this copyThis is the design as agreed before implementation, kept as a record of the reasoning. The headers and the Sphinx documentation are the reference for the current API. Phase 1 changed a few details:
  • Faces are oriented by their sorted axes (xy, xz, yz), not by the right-hand rule on their normal (yz, zx, xy). Every dual cell is oriented by its sorted axes in the same way. See include/declib/stag/orientation.hpp.
  • The PETSc exception is declib::PetscException, because a class named PetscError hid PETSc's own PetscError() in code that says using namespace declib.
  • Essential conditions are attached with FormSpace::with_essential and imposed on an assembled system with apply_essential. Natural boundary data other than zero is planned for phase 2.
  • In Python, mappings, orientations and boundary types are the enums dl.GridMapping, dl.Orientation and dl.Boundary, and Form.to_numpy() returns the owned values as a flat array.
  • Phase 1 was verified on CPU (OpenMP); GPU runs are still to come.

This document proposes the class structure and public interfaces for DecLib++, a discrete exterior calculus library on Kokkos and PETSc with a Python interface. It covers topology, the straight–twisted grid mapping, geometry, scalar and vector-bundle valued forms, and linear, bilinear and nonlinear operators. The first implementation targets topologically structured grids through DMStag. Every interface is written so that a DMPlex backend can be added later without changing user code.

Goals and principles

  • Separate topology from metric. Topology, the straight–twisted mapping and geometry are three distinct objects. Operators that are metric-free (d, the duality pairing, the cup-product wedge) depend only on topology and mapping, so their exactness properties cannot be broken by a geometry change.
  • Forms carry their type. Every form knows its degree, its orientation (straight or twisted) and its fiber (scalar or bundle-valued). Where it lives on the grid is derived from that type through the mapping, never stored separately. Operators check types when they are constructed, not when they are applied.
  • Virtual dispatch at operator granularity only. Abstract base classes describe topology, geometry, spaces and operators. Inner loops are Kokkos kernels templated on the dimension and the backend, with no virtual calls on device.
  • PETSc is the data and solver substrate. Form data lives in PETSc Vecs of type VECKOKKOS, layouts come from the DM, and every linear operator can present itself as a PETSc Mat (matrix-free shell or assembled) so KSP, SNES and TS work unchanged.
  • Discrete identities are part of the contract. Each class lists the identities it guarantees (d∘d = 0, exact Stokes, adjointness of iX and its dual, Leibniz rule where it holds). The test suite is built from that list (§12).
  • One model, two languages. The Python interface mirrors the C++ classes one to one, so documentation, examples and tests read the same in both.

Architecture

The library is organised in layers. Each layer depends only on the layers below it.

Topology

A Topology is an oriented cell complex of dimension n together with its dual complex. It knows cell counts, incidence (the boundary operators ∂k) and orientations, and owns the parallel decomposition. It knows nothing about lengths, areas or coordinates.

enum class Complex { Primal, Dual };

/// All k-cells of one complex. Structured backends refine a CellSet into
/// per-axis strata (x-edges, y-edges, ...), see §3.1.
struct CellSet { Complex complex; int k; };

class Topology : public std::enable_shared_from_this<Topology> {
public:
  virtual ~Topology() = default;

  virtual int       dimension() const noexcept = 0;
  virtual MPI_Comm  comm() const noexcept = 0;
  virtual Backend   backend() const noexcept = 0;     // Stag, Plex

  /// Locally owned / ghosted / global counts of k-cells on either complex.
  virtual std::size_t num_owned(CellSet) const = 0;
  virtual std::size_t num_local(CellSet) const = 0;
  virtual PetscInt    num_global(CellSet) const = 0;

  /// Dual k-cells are in bijection with primal (n-k)-cells.
  CellSet dual_of(CellSet c) const;

  /// Signed incidence ∂_k : C_k -> C_{k-1}, assembled (generic, used by tests
  /// and by the generic sparse operator path). Structured kernels never call it.
  virtual Mat incidence(CellSet) const = 0;

  /// Boundary handling of the dual complex (see §3.2).
  virtual DualBoundary dual_boundary() const noexcept = 0;

  /// Halo width required by the widest operator stencil; fixed at creation.
  virtual int stencil_width() const noexcept = 0;
};

A structured topology is the logically Cartesian product complex. Cells are identified by an element index (i, j, k) plus a stratum, which is a DMStag location such as DMSTAG_LEFT. The dual of a cubical complex is again cubical, which is why the same DMStag can hold dual forms (§9).

The dual complex at boundaries

On periodic grids the dual complex is a closed cubical complex and the dual exterior derivative is exactly ±∂T. On non-periodic grids the dual cells around boundary vertices are truncated. The design exposes this as an explicit policy rather than a hidden convention:

enum class DualBoundary {
  Truncated,   // dual cells clipped at ∂M; dual d gains boundary-closure terms
  Extended     // dual complex includes cells on ∂M itself (a dual "boundary layer")
};

With Extended, the dual complex carries extra boundary cells so that the discrete Stokes theorem holds on the dual side including boundary terms, which is what weak boundary conditions need. Decided (Q2): Extended is the default; Truncated stays available.

Decision: boundary conditions (Q3)Essential conditions are constrained dofs on the FormSpace (relative cochains). Natural conditions enter through the extended dual boundary cells, where they appear as boundary terms of the dual exterior derivative.

Straight–twisted grid mapping

A continuous k-form is either straight (inner oriented, integrated over cells carrying an inner orientation) or twisted (outer oriented, sometimes called a pseudo-form or density). Primal cells carry inner orientations; dual cells inherit outer orientations from the primal cells they cross. A discretization must choose which complex hosts which kind of form. That choice is the GridMapping.

enum class Orientation { Straight, Twisted };

class GridMapping {
public:
  static GridMapping straight_on_primal();   // twisted forms on the dual
  static GridMapping twisted_on_primal();    // straight forms on the dual

  /// Complex hosting forms of this orientation.
  Complex host(Orientation) const noexcept;

  /// Cells on which a k-form of this orientation is stored. A k-form always
  /// lives on k-cells of its host complex: CellSet{host(o), k}.
  CellSet cells(int k, Orientation o) const noexcept;

  /// The same cells expressed as primal cells; used by structured storage,
  /// since a dual k-cell is indexed by its primal (n-k)-cell.
  CellSet storage_cells(int k, Orientation o, int n) const noexcept;
};

Both mappings occur in practice. Straight-on-primal is the usual DEC convention (potentials and circulations on the primal grid, fluxes and densities on the dual). Twisted-on-primal is the finite-volume and TRiSK convention, where mass is a twisted n-form on primal cells and vorticity lives on dual vertices. The mapping is a runtime value held by the DiscreteManifold, so one topology and geometry can serve both.

The Hodge star maps a straight k-form to a twisted (n−k)-form. Under either mapping both sit on the same DMStag stratum, so the diagonal Hodge star is a pointwise scaling, which the table makes visible.

Geometry

A Geometry supplies everything metric: vertex coordinates, the placement of dual vertices, primal and dual cell measures, and whatever else a metric operator needs. It holds a reference to its topology and never modifies it. Measures are themselves stored as cochains on the topology, so geometric data uses the same layouts, halos and Kokkos views as forms.

enum class DualPlacement { Circumcentric, Barycentric };

class Geometry {
public:
  virtual ~Geometry() = default;
  virtual const Topology& topology() const noexcept = 0;
  virtual DualPlacement    dual_placement() const noexcept = 0;

  /// |σ| for every k-cell of a complex (length, area, volume; 1 for vertices).
  virtual const CellField& measure(CellSet) const = 0;

  /// Coordinates of primal vertices and dual vertices (Dim components each).
  virtual const CellField& coordinates(Complex) const = 0;

  /// True when the metric is a diagonal tensor in the grid frame (uniform or
  /// rectilinear). Lets operators pick cheaper kernels.
  virtual bool is_orthogonal() const noexcept = 0;

  /// De Rham map R: integrate a callable form over every cell of a family.
  /// Used for initial data, manufactured solutions and convergence tests.
  virtual void de_rham(const FormFunction&, Form&, Quadrature = {}) const = 0;
};

Connections for bundle-valued forms

Covariant exterior derivatives on non-trivial bundles need parallel transport between fibers. That is metric-like data, so it lives beside the geometry:

class Connection {
public:
  virtual const Bundle& bundle() const noexcept = 0;
  /// Transport U(τ→σ) ∈ GL(r) from the fiber at a (k-1)-cell τ to the fiber at
  /// an incident k-cell σ, for every incidence pair of the host complex.
  virtual const TransportField& transport(CellSet k_cells) const = 0;
  virtual bool is_flat() const noexcept = 0;   // then d∇ ∘ d∇ = 0
};

The trivial bundle with the Cartesian frame has the identity connection, which is the only one needed in phase 2.

Differential forms

Forms are split into a type, a space and an element, the same way PETSc separates a DM from a Vec.

Form type and bundle

enum class BundleKind { Scalar, Trivial, Tangent, Cotangent, Custom };

class Bundle {
public:
  static Bundle scalar();                         // rank 1
  static Bundle trivial(int rank);              // R^r, global frame
  static Bundle tangent(int n);                 // vector-valued forms
  static Bundle cotangent(int n, Orientation);  // covector-valued (e.g. momentum)

  BundleKind  kind() const noexcept;
  int         rank() const noexcept;          // fiber dimension r
  Orientation fiber_orientation() const noexcept;
  bool        is_trivial() const noexcept;
};

struct FormType {
  int         degree;        // k, 0 ≤ k ≤ n
  Orientation orientation;   // straight or twisted
  Bundle      bundle;        // scalar unless stated
  bool operator==(const FormType&) const = default;
};

An E-valued k-form stores one fiber element (r numbers) per k-cell, expressed in a frame attached to that cell. For a trivial bundle the frame is global, so d, ⋆ and the pairing act componentwise. For tangent and cotangent bundles on a non-Cartesian geometry the frame varies, and operators that compare fibers at different cells must go through a Connection. The fiber orientation lets the type express objects such as a covector-valued twisted n-form (momentum density) or a twisted form valued in straight 1-forms.

Form space

class FormSpace {
public:
  virtual ~FormSpace() = default;
  const DiscreteManifold& manifold() const noexcept;
  const FormType&         type() const noexcept;
  CellSet                 cells() const noexcept;   // from the mapping

  virtual DM          dm() const noexcept = 0;  // DMStag (or DMPlex + PetscSection)
  virtual std::size_t local_size() const = 0;
  virtual PetscInt    global_size() const = 0;

  Form zeros() const;
  Form from_function(const FormFunction&) const;  // de Rham map

  /// The space this one pairs with: same mapping, opposite orientation,
  /// degree n-k, dual bundle. ⟨·,·⟩ : V × V.dual_space() → R is metric-free.
  std::shared_ptr<const FormSpace> dual_space() const;

  /// Constrained dofs for essential boundary conditions (Q3). Natural
  /// conditions are not set here; they live on extended dual boundary cells.
  void set_constraint(const BoundaryCondition&);
};

stag::FormSpace<Dim> builds its DM with DMStagCreateCompatibleDMStag from the topology's base DM, putting r dofs on exactly the strata named by mapping.storage_cells(k, orientation) and zero elsewhere. All spaces therefore share one parallel decomposition, and a vector-bundle valued space differs from a scalar one only in its dof count per stratum.

Form

class Form {
public:
  explicit Form(std::shared_ptr<const FormSpace>);
  const FormSpace& space() const noexcept;
  const FormType&  type()  const noexcept;

  Vec  global_vec() const noexcept;    // owned values, VECKOKKOS
  Vec  local_vec();                    // ghosted, lazily refreshed
  void update_ghosts();                // DMGlobalToLocal, tracked by a dirty flag

  /// Device views. Read-only views refresh ghosts first.
  FormView<const Scalar> view() const;
  FormView<Scalar>       view_mut();

  /// Vector-space operations forward to PETSc.
  Form& axpy(Scalar a, const Form& x);
  Form& scale(Scalar a);
  Form  copy() const;
};

/// Kokkos-accessible view; the structured version is indexed by element
/// index, stratum direction and fiber component.
template <class T, int Dim>
struct stag::FormView {
  KOKKOS_INLINE_FUNCTION T& operator()(int i, int j, int dir, int comp = 0) const;  // Dim = 2
};

A Form owns its Vec and has value semantics for copying data (copy()) but cheap move. Spaces, manifolds, topologies and geometries are immutable after setup and shared through shared_ptr<const T>.

Decision: runtime form typesThe scaffold's placeholder uses Cochain<Degree, Kind> with compile-time degree. This design makes the degree and orientation runtime values and checks them when operators are built. Reasons: the Python interface needs runtime types anyway; bundle-valued and unstructured spaces multiply template parameters; operator composition such as ⋆⁻¹ d ⋆ d is assembled once, so a runtime check at construction costs nothing per apply. The spatial dimension stays a template parameter inside the structured backend, where it shapes the kernels. A thin typed C++ facade can be added on top later. Decided (Q1): runtime form types.
Decision: scalar type (Q6)Scalar is PetscScalar, and only real PETSc builds are supported. CMake configuration fails with a clear message when PETSc was built with complex scalars.

Operator framework

Operators are objects that are built once (type checks, stencil and geometry factors precomputed, optional assembly) and applied many times. There are four kinds.

Linear operators

class LinearOperator : public std::enable_shared_from_this<LinearOperator> {
public:
  virtual ~LinearOperator() = default;
  virtual const FormSpace& domain() const noexcept = 0;
  virtual const FormSpace& range()  const noexcept = 0;

  /// y = A x  and  y += a A x
  virtual void apply(const Form& x, Form& y) const = 0;
  virtual void apply_add(const Form& x, Form& y, Scalar a = 1) const;

  /// Algebraic transpose: range-space values back to domain-space values.
  virtual void apply_transpose(const Form& y, Form& x) const;

  /// Adjoint under the duality pairing: the operator A† : range.dual_space()
  /// -> domain.dual_space() with ⟨A x, β⟩ = ⟨x, A† β⟩ exactly.
  virtual std::shared_ptr<LinearOperator> pairing_adjoint() const;

  /// PETSc views of the operator.
  Mat shell() const;                                     // MATSHELL, matrix-free
  virtual Mat assemble(MatType = MATAIJKOKKOS) const;    // explicit sparse

  virtual bool is_diagonal() const noexcept { return false; }
  virtual std::string name() const;
};

// Lazy composition, type-checked at construction:
OpPtr operator*(OpPtr A, OpPtr B);     // A∘B; requires B.range() == A.domain()
OpPtr operator+(OpPtr A, OpPtr B);     // same domain and range
OpPtr operator*(Scalar a, OpPtr A);
OpPtr inverse(OpPtr A, KSPOptions = {}); // exact if diagonal, else wraps a KSP
OpPtr identity(SpacePtr V);

Composite nodes (ProductOperator, SumOperator, ScaledOperator, InverseOperator, PairingAdjointOperator) apply lazily with pooled temporaries. assemble() on a product uses MatMatMult; on a diagonal inverse it inverts entries; on a general inverse it refuses. Defaults for pairing_adjoint() are computed from apply_transpose() and the sign pattern of the pairing, so every operator has one; operators with a cheaper dedicated kernel override it.

Bilinear operators

class BilinearOperator {
public:
  virtual const FormSpace& left()  const noexcept = 0;
  virtual const FormSpace& right() const noexcept = 0;
  virtual const FormSpace& range() const noexcept = 0;

  /// c = B(a, b)  and  c += s B(a, b)
  virtual void apply(const Form& a, const Form& b, Form& c) const = 0;
  virtual void apply_add(const Form& a, const Form& b, Form& c, Scalar s = 1) const;

  /// Freeze one argument to get a linear operator. The frozen form is held by
  /// reference, so updating `a` updates the operator (useful inside Newton).
  virtual OpPtr fix_left(const Form& a) const;    // b ↦ B(a, b)
  virtual OpPtr fix_right(const Form& b) const;   // a ↦ B(a, b)
};

Every bilinear operator gets its Jacobian for free: ∂B(a,b) = B(δa, b) + B(a, δb) = fix_right(b) δa + fix_left(a) δb.

Nonlinear operators and functionals

class NonlinearOperator {
public:
  virtual const FormSpace& domain() const noexcept = 0;
  virtual const FormSpace& range()  const noexcept = 0;
  virtual void  apply(const Form& x, Form& y) const = 0;
  virtual OpPtr jacobian(const Form& x) const = 0;   // linearization at x

  /// Hooks for SNES: residual and Jacobian callbacks bound to this operator.
  void attach(SNES, const Form& rhs) const;
};

/// Scalar-valued nonlinear map, e.g. an energy or a Hamiltonian.
class Functional {
public:
  virtual const FormSpace& domain() const noexcept = 0;
  virtual Scalar value(const Form& x) const = 0;
  /// Variational derivative δF/δx as an element of domain().dual_space(),
  /// so that dF(x)[δx] = ⟨δx, δF/δx⟩ with the metric-free pairing.
  virtual void gradient(const Form& x, Form& g) const = 0;
};

Putting variational derivatives in the dual space is deliberate. It is what Hamiltonian and Poisson-bracket discretizations need: a bracket built from d, ⋆, wedge and the interior product and its pairing adjoint is antisymmetric by construction, so energy conservation holds at the discrete level.

DEC operators

Each concrete operator is constructed from the space(s) it acts on plus a scheme option. Construction validates the form types and picks the backend kernel from topology().backend(). Schemes are also selectable through the PETSc options database (for example -declib_hodge_type diagonal).

Exterior derivative

class ExteriorDerivative final : public LinearOperator {
public:
  /// Domain: any k-form space with k < n. Range: manifold.space(k+1, same
  /// orientation, same bundle). Bundle-valued forms act componentwise and
  /// require a trivial bundle; use CovariantDerivative otherwise.
  static std::shared_ptr<ExteriorDerivative> create(SpacePtr domain);
};

On the primal complex dk = ∂k+1T. On the dual complex the dual derivative is d̃k = ±∂n−k, with the sign fixed by the orientation convention and boundary closure terms set by DualBoundary. Its pairing_adjoint() is the dual-complex derivative up to sign, which is the discrete integration-by-parts identity. On DMStag it is a two-point difference stencil per axis with no stored coefficients.

Hodge star

enum class HodgeScheme { Diagonal, Galerkin, HighOrder };

class HodgeStar final : public LinearOperator {
public:
  /// Domain: k-form space of either orientation. Range: (n-k)-form space of
  /// the opposite orientation (and opposite complex under the mapping).
  static std::shared_ptr<HodgeStar> create(SpacePtr domain, HodgeScheme = HodgeScheme::Diagonal);
  HodgeScheme scheme() const noexcept;
};

Diagonal is the ratio |⋆σ|/|σ| and requires an orthogonal geometry. Galerkin uses tensor-product Whitney forms on the cube, is symmetric positive definite on any mapped geometry, and is not diagonal, so its inverse is a solve. HighOrder reserves room for wider-stencil stars. The star applied twice multiplies by (−1)k(n−k) in the continuum; the discrete pair ⋆k, ⋆n−k is built to satisfy that relation exactly for the diagonal scheme.

Wedge product

/// Scheme selector. The concrete schemes are deferred (Q4); candidates include
/// cubical cup product, averaged cup product and interpolated wedges.
class WedgeScheme;

class Wedge final : public BilinearOperator {
public:
  /// Result orientation: straight∧straight = straight, straight∧twisted =
  /// twisted, twisted∧twisted = straight. Degree k+l ≤ n.
  static std::shared_ptr<Wedge> create(SpacePtr left, SpacePtr right, const WedgeScheme&,
                                     FiberProduct = FiberProduct::scalar());
};

Which wedge schemes to provide, and which is the default, is deferred (Q4). The interface only fixes what any scheme must declare: whether it is metric-free (same-complex products such as a cubical cup product are purely topological) or needs geometry (products across primal and dual complexes need interpolation weights), and which identities it satisfies exactly (Leibniz rule, graded commutativity), so tests can be selected per scheme. The scheme is a required argument with no default. For bundle-valued forms a FiberProduct supplies the pointwise fiber map E1 × E2 → E3 (dot, cross, matrix product).

Interior product and its adjoint

enum class VectorRepresentation {
  Flux,         // X given as the twisted (n-1)-form i_X(vol)
  Circulation   // X given as the straight 1-form X♭
};

class InteriorProduct final : public BilinearOperator {
public:
  /// left(): space of the vector field X (its representation is read from
  /// the space type). right(): k-forms α. range(): (k-1)-forms i_X α.
  static std::shared_ptr<InteriorProduct> create(SpacePtr vector_space, SpacePtr form_space,
                                               const InteriorScheme&);   // schemes deferred (Q4)

  /// The adjoint bilinear operator (X, β) ↦ i_X† β, where β lives in
  /// range().dual_space() and the result in right().dual_space(), with
  ///   ⟨ i_X α, β ⟩ = ⟨ α, i_X† β ⟩   for all X, α, β, to round-off.
  std::shared_ptr<InteriorProductAdjoint> adjoint() const;
};

class InteriorProductAdjoint final : public BilinearOperator { /* built only via adjoint() */ };

In the continuum the adjoint of iX under the wedge pairing is (−1)k+1 iX acting on the complementary twisted forms. In the discrete setting the two cannot both be defined independently and still be exactly adjoint, so the library defines one and derives the other: iX† is constructed as the pairing adjoint of fix_left(X), with a dedicated stencil kernel that is tested against that definition. This is the property that makes discrete Lie derivatives and Hamiltonian brackets conserve energy.

End-to-end example

using namespace declib;
auto topo = stag::Topology<2>::create(PETSC_COMM_WORLD, {.cells = {128, 128}});
auto geom = stag::UniformGeometry<2>::create(topo, {.lengths = {1.0, 1.0}});
auto M = DiscreteManifold::create(topo, geom, GridMapping::straight_on_primal());

auto V0  = M->space(0, Orientation::Straight);   // primal vertices
auto V1  = M->space(1, Orientation::Straight);   // primal edges
auto tV1 = M->space(1, Orientation::Twisted);    // dual edges

auto d0 = ExteriorDerivative::create(V0);        // Λ0 → Λ1
auto s1 = HodgeStar::create(V1);                 // Λ1 → tΛ1
auto d1 = ExteriorDerivative::create(tV1);       // tΛ1 → tΛ2 (dual cells)
auto s0 = HodgeStar::create(V0);                 // Λ0 → tΛ2
auto lap = inverse(s0) * d1 * s1 * d0;                        // checked: spaces chain correctly

Form u = V0->from_function(manufactured_u), f = V0->zeros();
lap->apply(u, f);
KSP ksp; /* ... */ KSPSetOperators(ksp, lap->shell(), s0->assemble());

Each stag::FormSpace has its own compatible DMStag with dofs only on its strata, created with DMSetVecType(dm, VECKOKKOS). Device access goes through VecGetKokkosView on the local vector, wrapped in an unmanaged Kokkos::View<Scalar****, LayoutRight> indexed (k, j, i, slot), with slots resolved once per space from DMStagGetLocationSlot. stag::FormView hides the slot arithmetic.

Kernels

  • One functor per operator and scheme, templated on Dim and the GridMapping case, launched with Kokkos::MDRangePolicy<Kokkos::Rank<Dim>> over the owned box.
  • Halo exchange happens before a kernel through Form::view(); kernels never communicate.
  • assemble() uses MatSetPreallocationCOO / MatSetValuesCOO with indices produced on device, so assembled matrices are also built on the GPU.
  • Uniform geometry passes spacings as kernel arguments; other geometries pass views of their measure fields.

Orientation conventions

Primal edges point along +axis; primal faces are oriented by their normal axis through the right-hand rule (yz, zx, xy); elements are positively oriented. A dual k-cell carries the outer orientation induced by the primal (n−k)-cell it crosses. The convention is written down once in stag/orientation.hpp, and the sign tables of d̃, ⋆ and the pairing are generated from it so they cannot drift apart.

Nothing above the backend layer refers to DMStag. Adding unstructured grids means adding implementations, not changing interfaces.

Two choices keep this cheap. First, dual cells are always indexed by their primal partner, on both backends, so GridMapping needs no backend logic. Second, every operator has a generic fallback that applies its assembled matrix, so a new backend runs end to end as soon as incidence() and the geometric measures exist, and fast kernels can follow operator by operator.

Python interface

Bindings are a pybind11 compiled module declib._core with a thin pure-Python layer for docstrings and conveniences, matching the docs scaffold. Vec, Mat and DM handles cross the boundary as petsc4py objects.

import declib as dl

topo = dl.StagTopology(cells=(128, 128), boundary="periodic")
geom = dl.UniformGeometry(topo, lengths=(1.0, 1.0))
M = dl.DiscreteManifold(topo, geom, mapping=dl.Mapping.STRAIGHT_ON_PRIMAL)

V0, V1, tV1 = M.space(0, dl.STRAIGHT), M.space(1, dl.STRAIGHT), M.space(1, dl.TWISTED)
d0, d1 = dl.ExteriorDerivative(V0), dl.ExteriorDerivative(tV1)
s0, s1 = dl.HodgeStar(V0), dl.HodgeStar(V1)
lap = dl.inverse(s0) @ d1 @ s1 @ d0

u = V0.from_function(lambda x, y: np.sin(2*np.pi*x) * np.sin(2*np.pi*y))
f = lap(u)                 # apply
A = lap.assemble()         # petsc4py.PETSc.Mat
arr = f.to_numpy()         # host copy of owned values, shaped by stratum

@ composes operators, calling an operator applies it, and bilinear operators accept B(a, b) and B.fix_left(a). Python subclasses of LinearOperator and NonlinearOperator are allowed (host execution) so users can prototype operators before writing a kernel.

Decisions

The six open questions were decided by Chris on 23 October 2026.

  1. Form types are runtime values. FormType is checked when operators are constructed; Dim stays a template parameter inside the structured backend.
  2. The dual boundary treatment is Extended. The dual complex includes cells on the boundary, so the discrete Stokes theorem holds with boundary terms. Truncated stays available.
  3. Boundary conditions: essential conditions are constrained dofs on the FormSpace; natural conditions enter through the extended dual boundary cells.
  4. Wedge and interior product schemes are deferred. The interfaces take a scheme argument with no default; concrete schemes are chosen when phase 2 starts.
  5. Bindings use pybind11.
  6. Scalars are PetscScalar, real builds only. Complex PETSc builds are rejected at configure time.
